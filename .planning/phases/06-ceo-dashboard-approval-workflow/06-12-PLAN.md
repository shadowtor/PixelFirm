  <context>
/ceo and /ceo/api must be same-origin (no CORS plugin is allowed, and the Access cookie is per host).
Today only apps/api is deployed, on test.pixelfirm.dev, behind the pixelfirm-test tunnel. Either
choice is reversible (routing config); neither changes code. The office route will also be served,
but without a baked browser token it shows its disconnected banner until Phase 7 builds the stream route.
  </context>
  <options>
    <option id="traefik-paths">
      <name>Two Coolify apps, Traefik path routing (recommended, research default)</name>
      <pros>API keeps its app and FQDN; API paths (/ceo/api, /ceo/ws, /events, /ws, /ws/browser, /admin, /health) route to it, everything else to a new static web app; no proxy code in the repo.</pros>
      <cons>Relies on Coolify's path-based FQDN handling; any automatic strip-prefix on the API paths must be turned off, or /ceo/api breaks.</cons>
    </option>
    <option id="nginx-proxy">
      <name>One public web app whose nginx proxies the API paths internally</name>
      <pros>Routing lives in apps/web/nginx.conf in git and is reviewable; one public router; the API loses its public FQDN.</pros>
      <cons>nginx must forward WebSocket upgrades, Cf-Access-Jwt-Assertion, Cookie, Origin and X-Forwarded-For correctly; one more hop.</cons>
    </option>
