<objective>
The control-plane half of the approval round trip, split out of the 06-01 tracer so each plan stays
inside the context budget. 06-01 proved that a decision frame in the shared `WorkerDownlinkSchema`
shape resolves the worker's parked `canUseTool`; this plan makes the control plane produce that
frame: a CEO decision POSTed to `/ceo/api/decisions/:decisionId` is appended as PRIVATE
`ceo.decision_made` (D-04, CEO-05) and sent down the owning worker's existing WebSocket. After this
plan the round trip works end to end: API to worker broker to runtime.

Security posture from the first commit that exposes the route: identity from the worker credential
only (the stamped workerId), a fail-closed dev auth path (D-11's Access JWT arrives in 06-05, inside
the same `requireCeo`), BROWSER_ACCESS_TOKEN never authorizes decisions (D-11), and the D-12 CSRF
guard (custom header + strict Origin allowlist + JSON body) before any database work.

Output: the worker-socket registry, server-side workerId stamping and ceo.* rules on /events, the
parsed env with the dev-bypass production guard, the dev-bypass `requireCeo`, the CSRF guard, and
the decision route with the per-action note and answers rules (D-07).

Not in this plan: Access JWT verification, `GET /ceo/api/me`, one-decision-per-request unique index
and 409s (06-05); the `/ceo/ws` feed and the office-feed PRIVATE filter (06-06); the worker wiring
`handleDownlink` to its socket (06-04).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /ceo/api/decisions | CEO decision input; untrusted until Origin/CSRF/auth pass |
| control plane -> worker WS downlink | closed message set; only the owning worker receives a decision |
| worker -> /events | worker-authored ceo.* events; identity from the credential only |

| T-06-13-02 | Tampering | CSRF on POST | high | mitigate | requireCsrf: exact Origin allowlist (empty by default), X-PixelFirm-CSRF: 1, JSON content-type, before any DB work (403-before-404 test).
