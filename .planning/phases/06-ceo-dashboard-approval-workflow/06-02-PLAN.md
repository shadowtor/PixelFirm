<objective>
Close the two ways a CEO-gated call could still run without an explicit CEO approve, and make the
parked call survive CEO think-time.

1. Settings allow rules shadow `canUseTool` (research Pitfall 1): this repo's own
   `.claude/settings.local.json` allows `git push`, `git merge`, `pnpm add` and `mcp__coolify__deploy`.
   A `PreToolUse` hook returning `ask` outranks `allow`, forcing the call back to `canUseTool`.
2. The classifier misses whole CEO-04 categories (dependency changes, pushes that deploy, MCP tools,
   and production changes made by editing deployment config or calling a deploy hook). Widening needs
   the user's confirmation because it adds CEO round-trips (research Open Question 2), so this plan
   opens with that decision, including an explicit sign-off on whatever stays ungated.
3. D-03 / D-02: the watchdog must not kill a parked session, the Notification hook must not
   double-request, and aborted or superseded parked calls must deny and leave an expiry record.

Output: a runtime where the only way a classified call runs is the SDK promise resolving to the CEO's
approve for that exact call.
</objective>
