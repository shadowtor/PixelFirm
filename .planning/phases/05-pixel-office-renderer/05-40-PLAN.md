<objective>
Close G-05-1b: a handoff currently renders as two truncated identifiers joined by an arrow and reads
as a debug banner rather than a handoff.

Root cause, found by reading the code rather than the screenshot: `handoff-choreography.ts` resolves
the label with `getTaskTitle(taskId) ?? taskId` at both call sites. When no `task.created` carrying a
title has arrived — which is every handoff in the live stack today, because no in-repo producer emits
one — the template interpolates the raw TASK ID as if it were a human title. The 14-character cap
then chops it to an ellipsis-terminated fragment, the receiver's name falls back to its agent id and
gets chopped the same way, and the arrow-joined result is literally two ids side by side. The caps
are not the defect; painting an id as a title is.

Two fixes, both inside the deterministic template contract: never paint an id as a title, and make
both lines verb-led so a bubble reads as an action even when one value is cut. Third, since this
plan changes the text shape, it closes review finding WR-01 in the same pass — the renderer's frame
record still attributes a drawn rect by bubble TEXT while the FSM attributes the speaker by
`bubbleTextTaskId`, and the verifier flagged that as worth closing before Phase 6 hit-tests `box`.

Purpose: a handoff must look like a handoff.
Output: verb-led nullable-title templates, an id-never-painted guard, WR-01 closed, and the phase's
final live review frames with all four UAT gaps fixed.
</objective>
