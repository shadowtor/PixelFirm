# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Retroactive note:** This UI-SPEC is written after Phase 5 (05-01 through 05-04) was already planned and executed, to satisfy the plan-phase UI safety gate before a `--gaps` closure re-plan. It documents the design/interaction contract as ACTUALLY shipped (verified against `packages/pixel-office`, `apps/web`, and `05-VERIFICATION.md`), and flags the specific rendering gaps the closure plan must resolve — it does not propose a new design.

| Property | Value |

**Why `Tool: none`:** This phase is not a forms/components web UI — it is a forked, hand-rolled Canvas2D pixel-art rendering engine (`packages/pixel-office`, forked from `pixel-agents-hq/pixel-agents`, MIT). No `components.json`, Tailwind, or PostCSS config exists anywhere in the repo (confirmed: `ls components.json tailwind.config.* postcss.config.*` returns nothing). `apps/web`'s only DOM element outside the `<canvas>` is one inline-styled `<footer>` (attribution, OFFICE-02). shadcn does not apply to a raw `CanvasRenderingContext2D` sprite renderer — introducing it would not serve this phase's actual UI surface.

**Asset format contract (lock in for any new icon the closure plan adds):**
- Exactly 11 columns × 13 rows, `pixels: string[][]` — empty string `""` cells are transparent.
- `palette: Record<string, hexColor>` — pixel values are palette keys, never raw hex inline.
- Every glyph must be a **distinct silhouette**, not a recolour of another glyph (OFFICE-03's grayscale/compressed-video legibility requirement — colour alone must never be the only signal).
- Every glyph used by a frozen status (`STATUS_MAP` `frozen: true`) has a closed 1 px near-black outline (relative luminance <= 0.03), every other cell >= 3:1 against it, the outline >= 3:1 against `FALLBACK_FLOOR_COLOR`, the outline or main fill >= 3:1 against each MetroCity floor tile's mean colour (05-26), and frozen glyph masks differ pairwise in >= 20 cells; enforced by `bubbleSprites.test.ts` (05-23, G-05-2).

## Spacing Scale

Declared values (must be multiples of 4) — **applies to the DOM overlay only** (the `<footer>` element). The canvas itself is pixel-art with its own fixed grid unit (see Exceptions).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Footer vertical padding |
| sm | 8px | Footer horizontal padding |
| md | 16px | — (unused this phase — no other DOM chrome exists) |
| lg | 24px | — (unused this phase) |
| xl | 32px | — (unused this phase) |
| 2xl | 48px | — (unused this phase) |
| 3xl | 64px | — (unused this phase) |

**Exceptions:** The canvas's actual layout unit is the pixel-art **tile grid**, not the 8-point DOM scale — `TILE_SIZE = 16px`, office grid `DEFAULT_COLS × DEFAULT_ROWS = 20 × 11` tiles (`packages/pixel-office/src/constants.ts`), giving a `320×176px` office grid that is never presented at native size (05-21, G-05-1a): it is always shown at an integer scale N ≥ `MIN_DISPLAY_SCALE` (3), where N is the largest integer that fits the viewport minus the 24px footer allowance (`displayScaleFor`). The canvas backing store is `320N × 176N`, the engine draws every frame at zoom N, the CSS box equals the backing store, and the canvas uses `image-rendering: pixelated`. Any new on-canvas element (a bubble icon, a badge, a future dialogue box) must align to this 16px tile grid, not the 4px DOM spacing scale.

**Office layout (05-24/05-25/05-26, G-05-1e):** `packages/pixel-office/src/layout/office-layout.json` is the single source. Pods of two seats sit behind 3-tile desks at cols 1/5/9/13 on rows 5/9; the seats are on rows 4/8 facing the viewer. Lanes run along cols 4/8/12/16 and rows 3/6/7. Standing spots are (17,4) (18,4) (17,8) (18,8). Decor sits on cols 17-18 and the top wall. Every seat and standing spot is on row 4 or 8, so the strip under their feet holds only furniture, never an agent or a glyph (05-28 guards this with a layout-data test).

**Handoff dialogue (shipped 05-13, reshaped by 05-28 and 05-29 for G-05-4/G-05-1b):** `Character.bubbleText` (`packages/pixel-office/src/handoff/dialogue-templates.ts`) is drawn by `renderScene`'s dialogue pass (`engine/renderer.ts`, `drawDialogue` / `resolveDialogueBox`) in `DIALOGUE_FONT_PX` (5) world px `monospace`, i.e. 5N device px at display scale N (>= 15px at the minimum scale 3). The text sits in a speech bubble `DIALOGUE_BOX_HEIGHT_PX` (9) world px tall with a 1px ink border, `DIALOGUE_BOX_PAD_X_PX` (2) horizontal padding and a `DIALOGUE_TAIL_PX` (2) tail at the speaker. The bubble hangs from the speaker's foot line (y = foot line + 2); the requested bubble spans sender to receiver (centred on the pair's midpoint), and it is clamped only to the floor interior (x 16..304 at zoom 1). Clearance from every other agent and glyph is proven by the layout-data guard in `renderer.test.ts`, which goes red on any layout edit that breaks it. Pass order unchanged: all sprites, then all dialogue bubbles, then all state glyphs, so a transient line never hides a state signal. **Superseded (05-28/05-29):** the earlier 11px canvas scale and the box placed above the speaker's glyph slot and clamped at y = 0 no longer apply; the DOM footer keeps 11px. **16px-grid interpretation (05-13 assumption A2):** the bubble is anchored to its speakers inside the tile-grid canvas rather than tile-aligned; the Spacing Scale exception's "align to the 16px tile grid" is read as "live inside the tile-grid canvas, owner-anchored".

| Destructive | `#d62828` (red, `bubble-blocked.json`/`bubble-failed.json`) | Reserved for the `blocked` and `failed` state icons only |
| Dialogue box | `#dcdcdc` (`DIALOGUE_BOX_COLOR`) | Handoff speech-bubble fill only (05-28, G-05-4/G-05-1b; text shortened by 05-29). Achromatic, light; never an accent and never a state signal. `renderer.test.ts` colour guard proves no character (all twelve identity hues) or glyph palette, floor, wall or office sprite paints it |
| Dialogue text | `#161616` (`DIALOGUE_TEXT_COLOR`) | Handoff speech-bubble ink: border, tail and text (05-28/05-29). Achromatic and dark, so antialiased blends with the fill stay achromatic; same `renderer.test.ts` guard |

**Accent reserved for:** the bubble/badge icon glyph pixels rendered above a character's head to signal `AgentStatus` (blocked / failed / completed / planning / researching / testing / reviewing / discussing / deploying / waiting_for_ceo / waiting_for_agent). Never for anything else — specifically never for a character's base sprite colour.

**Locked project rule (do not violate in the closure plan):** per-agent identity colour uses `Character.hueShift`/`palette` via `colorize.ts`'s `adjustSprite`/`colorizeSprite` — this is a *separate, already-claimed* colour channel from state signaling. `RESEARCH.md` Pattern 2 explicitly rejected tint/hue as a state-signal mechanism because it collides with this per-agent identity system and because "tints get lost on compressed stream video and don't stop the sprite from reading as active" (05-CONTEXT.md D-03's own rationale). The only sanctioned non-color state signal beyond the icon overlay is the `frozen` pose (idle-loop animation suppressed) and, for `deploying` only, `frameSpeedMultiplier` (animation speed, never tint). Any closure-plan implementation that reaches for a colour/tint change to signal status is a contract violation.
