# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Retroactive note:** This UI-SPEC is written after Phase 5 (05-01 through 05-04) was already planned and executed, to satisfy the plan-phase UI safety gate before a `--gaps` closure re-plan. It documents the design/interaction contract as ACTUALLY shipped (verified against `packages/pixel-office`, `apps/web`, and `05-VERIFICATION.md`), and flags the specific rendering gaps the closure plan must resolve — it does not propose a new design.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none (custom hand-authored pixel-JSON sprite icons — see Sprite & Icon Asset Inventory) |
| Font | monospace (system default; used only by the DOM attribution footer, no font ever loaded for canvas rendering) |

**Why `Tool: none`:** This phase is not a forms/components web UI — it is a forked, hand-rolled Canvas2D pixel-art rendering engine (`packages/pixel-office`, forked from `pixel-agents-hq/pixel-agents`, MIT). No `components.json`, Tailwind, or PostCSS config exists anywhere in the repo (confirmed: `ls components.json tailwind.config.* postcss.config.*` returns nothing). `apps/web`'s only DOM element outside the `<canvas>` is one inline-styled `<footer>` (attribution, OFFICE-02). shadcn does not apply to a raw `CanvasRenderingContext2D` sprite renderer — introducing it would not serve this phase's actual UI surface.

**Asset format contract (lock in for any new icon the closure plan adds):**
- Exactly 11 columns × 13 rows, `pixels: string[][]` — empty string `""` cells are transparent.
- `palette: Record<string, hexColor>` — pixel values are palette keys, never raw hex inline.
- Every glyph must be a **distinct silhouette**, not a recolour of another glyph (OFFICE-03's grayscale/compressed-video legibility requirement — colour alone must never be the only signal).
- Every glyph used by a frozen status (`STATUS_MAP` `frozen: true`) has a closed 1 px near-black outline (relative luminance <= 0.03), every other cell >= 3:1 against it, the outline >= 3:1 against `FALLBACK_FLOOR_COLOR`, the outline or main fill >= 3:1 against each MetroCity floor tile's mean colour (05-26), and frozen glyph masks differ pairwise in >= 20 cells; enforced by `bubbleSprites.test.ts` (05-23, G-05-2).
- Placement (05-30, G-05-1c): a glyph is centred on its owner with its lowest ink row `BUBBLE_ICON_GAP_PX` (1) px above the owner's first opaque sprite row, computed per frame from the pixels (not the 16x32 frame box), so it sits on the visible head in every pose; the owner-bound fallback (CR-02) is kept. Every seat and standing spot keeps every glyph on the floor (y >= 16); enforced by `renderer.test.ts` and live TRUTH 4.
- **Added 05-32 (G-05-P5):** `bubble-waiting.json` additionally carries a **1x silhouette test** (`bubbleSprites.test.ts`, "1x hourglass silhouette") asserting the hourglass reads as an hourglass by shape alone at native scale: full-width 3-row caps, strictly triangular bulbs, exactly one 3 px-ink / 1 px-fill waist row, and more of the darker fill below the waist than above it. Any glyph whose identity depends on a specific silhouette feature (not just being distinct from the other eleven) should carry the same kind of test.

## Spacing Scale

Declared values (must be multiples of 4) — **applies to the DOM overlay only** (the `<footer>` element). The canvas itself is pixel-art with its own fixed grid unit (see Exceptions).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Footer vertical padding |
| sm | 8px | Footer horizontal padding |
| md | 16px | — (unused this phase — no other DOM chrome exists) |
| lg | 24px | — (unused this phase) |
| xl | 32px | — (unused this phase) |
| 2xl | 48px | — (unused this phase) |
| 3xl | 64px | — (unused this phase) |

**Exceptions:** The canvas's actual layout unit is the pixel-art **tile grid**, not the 8-point DOM scale — `TILE_SIZE = 16px`, office grid `DEFAULT_COLS × DEFAULT_ROWS = 20 × 11` tiles (`packages/pixel-office/src/constants.ts`), giving a `320×176px` office grid that is never presented at native size (05-21, G-05-1a): it is always shown at an integer scale N ≥ `MIN_DISPLAY_SCALE` (3). **Updated 05-31 (G-05-P6):** N is the largest integer that fits the **full viewport**, with **no footer allowance** — the attribution footer overlays the office's own bottom wall row instead of reserving DOM height below it. The canvas backing store is `320N × 176N`, the engine draws every frame at zoom N, the CSS box equals the backing store, and the canvas uses `image-rendering: pixelated`. Any remainder a non-multiple viewport leaves is split evenly (the canvas is centred in a full-viewport wrapper) and filled with `WALL_COLOR` — the office's own border colour, never black. The recommended OBS browser-source sizes are exact multiples of `320×176`: **1280×704 (4×), 1600×880 (5×), 1920×1056 (6×)**. The common 1280×720 and 1920×1080 also work — they present at 4× and 6× and leave an 8px or 12px `WALL_COLOR` strip above and below the office. Any new on-canvas element (a bubble icon, a badge, a future dialogue box) must align to this 16px tile grid, not the 4px DOM spacing scale.

**Office layout (05-24/05-25/05-26, G-05-1e):** `packages/pixel-office/src/layout/office-layout.json` is the single source. Pods of two seats sit behind 3-tile desks at cols 1/5/9/13 on rows 5/9; the seats are on rows 4/8 facing the viewer. Lanes run along cols 4/8/12/16 and rows 3/6/7. Standing spots are (17,4) (18,4) (17,8) (18,8). Decor sits on cols 17-18 and the top wall. Every seat and standing spot is on row 4 or 8. **Updated 05-33 (G-05-P1):** the strip under their feet holds the desks and monitors, so a speech bubble is no longer placed there unconditionally — see the handoff-dialogue placement rule under Typography, which scores four candidate positions against the frame's own glyphs, furniture and characters (05-28's layout-data band guard is gone with the band). **Updated 05-32 (G-05-P3):** a character **resting on its own seat** is drawn seated — sunk by `CHARACTER_SITTING_OFFSET_PX` (6) so its desk hides its lower body — **whatever its status** (idle, blocked, waiting_for_agent, waiting_for_ceo, failed, completed, typing), superseding 05-25's TYPE-only rule. Only an **off-seat** character stands full-body: one that is walking, one waiting at a handoff interaction tile, or one on a standing spot. Only the vertical offset depends on the seat — the drawn frame still comes from the pose (D-01), and `STATUS_MAP`, the pose FSM and the frozen flag (D-03) are unchanged, so a seated stuck agent still never animates as working. The glyph follows automatically, because placement above anchors it on the drawn frame's own head. **Updated 05-34 (G-05-P2):** handoff senders no longer wait on the receiver's seat row. They wait on **fixed interaction slots defined in layout data** — `office-layout.json`'s `interaction` block: the **central aisle row 6** at **column offsets +1, -1, +3, -3** from the receiver's home, taken in that order (`interactionSlotsFor`). A slot is only used when it is floor, not furniture, not itself a home, reachable, and no other character's seat or resting tile and no other live handoff target lies within one tile of it (diagonals included), so a second concurrent sender takes the next slot rather than standing beside the first. Because row 6 is the only interior row **two tiles from every seat and standing spot**, every slot is at least 2 tiles (Chebyshev) from every seat — a waiting sender can never be shoulder-to-shoulder with a seated or standing agent, which 05-27's outward seat-row search could not promise (it always returned the even column *between* two odd-column seats, leaving 2 px of air between three sprites in a line). Since no slot is a home, a waiting sender also never reads as sitting at someone else's desk (closes review WR-05). **The sender faces the receiver on the dominant axis** — UP across the desk to a row-4 receiver, DOWN to a row-8 one, sideways only when the column gap is the larger one. Measured over all 20 receiver homes in a full office: 86 neighbour pairs, tightest visible-ink separation **4 px** on some axis (desk overdraw included), against 2 px for the layout this supersedes.

Font family for the footer: `monospace` (unstyled system stack, no webfont loaded).

**Handoff dialogue (shipped 05-13, reshaped by 05-28 and 05-29 for G-05-4/G-05-1b):** `Character.bubbleText` (`packages/pixel-office/src/handoff/dialogue-templates.ts`) is drawn by `renderScene`'s dialogue pass (`engine/renderer.ts`, `drawDialogue` / `resolveDialogueBox`) in `DIALOGUE_FONT_PX` (5) world px `monospace`, i.e. 5N device px at display scale N (>= 15px at the minimum scale 3). The text sits in a speech bubble `DIALOGUE_BOX_HEIGHT_PX` (9) world px tall with a 1px ink border, `DIALOGUE_BOX_PAD_X_PX` (2) horizontal padding and a `DIALOGUE_TAIL_PX` (2) tail at the speaker. **Placement rule (05-33, G-05-P1):** the bubble is placed by trying four candidates **in order** and taking the best valid one — (1) **below**, hanging from the speaker's foot line (y = foot line + 2); (2) **above**, its bottom edge clear of the whole glyph band (`GLYPH_ROWS` + `BUBBLE_ICON_GAP_PX` + the tail above the speaker's head top, so it clears any glyph anchored there); (3) **right** of the speaker's sprite, at head height; (4) **left**, mirrored. Candidates 1-2 are centred on the midpoint of the speaker and its partner (the speaker alone when there is none) and clamped into the floor interior. A candidate is **valid** when the box lies wholly inside the floor interior (x 16..304, y 16..160 at zoom 1 — never across the canvas edge, never at x = 0) **and** covers no state glyph of any character, its own participants' included. Among valid candidates the winner has the **least desk overlap, then the least other-furniture overlap, then the least character overlap, then the earlier index** — so a desk-covering box is never chosen while a valid desk-free one exists. The obstacle model is therefore two-tier: glyphs and the floor bounds are **hard** limits; desks, then all other office furniture, then characters (each clipped at its foot line, plus any bubble already placed this frame) are **soft** and only rank the survivors. Desks outrank characters on the CEO's instruction: a bubble is transient and sits under the glyph pass, so crossing a seated agent's shoulders hides no state signal, whereas sitting on a desk and its monitors reads as clutter. The **tail always binds the box to its speaker** — a 1px ink rect from the box to the foot line (below), the head top (above), or across the gap to the sprite side (right/left). This supersedes 05-28's single under-the-feet band and its layout-data clearance guard (deleted): clearance is now a per-frame computation, proven by the scorer's unit cases plus a 40-scene sweep (20 receiver homes x requested/accepted, full 20-agent office) in `renderer.test.ts` that asserts the chosen candidate is valid and desk-free/furniture-free whenever any valid candidate is, and by live TRUTH 5. Pass order unchanged: all sprites, then all dialogue bubbles, then all state glyphs, so a transient line never hides a state signal. **Superseded (05-28/05-29):** the earlier 11px canvas scale and the box placed above the speaker's glyph slot and clamped at y = 0 no longer apply; the DOM footer keeps 11px. **16px-grid interpretation (05-13 assumption A2):** the bubble is anchored to its speakers inside the tile-grid canvas rather than tile-aligned; the Spacing Scale exception's "align to the 16px tile grid" is read as "live inside the tile-grid canvas, owner-anchored".

**Accent reserved for:** the bubble/badge icon glyph pixels rendered above a character's head to signal `AgentStatus` (blocked / failed / completed / planning / researching / testing / reviewing / discussing / deploying / waiting_for_ceo / waiting_for_agent). **Locked project rule (do not violate in the closure plan):** per-agent identity colour uses `Character.hueShift`/`palette` via `colorize.ts`'s `adjustSprite`/`colorizeSprite` — this is a *separate, already-claimed* colour channel from state signaling. `RESEARCH.md` Pattern 2 explicitly rejected tint/hue as a state-signal mechanism because it collides with this per-agent identity system and because "tints get lost on compressed stream video and don't stop the sprite from reading as active" (05-CONTEXT.md D-03's own rationale). The only sanctioned non-color state signal beyond the icon overlay is the `frozen` pose (idle-loop animation suppressed) and, for `deploying` only, `frameSpeedMultiplier` (animation speed, never tint). Any closure-plan implementation that reaches for a colour/tint change to signal status is a contract violation.
