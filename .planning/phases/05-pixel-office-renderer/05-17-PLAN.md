<objective>
Close 05-VERIFICATION.md gap 1 (05-REVIEW.md WR-02). Real events must never leave a handoff sender stuck mid-floor or a finished handoff's "accepts" line painted. Also close advisory WR-10: the live harness must positively see the accepted line paint.

Three live paths currently break the 05-13 prohibition:
1. A status update mid-walk. `upsertCharacterFromAgent` overwrites `ch.state` while a path is pending, and a frozen status makes `updateCharacter` return before moving anyone.
2. The sender despawns mid-sequence. `checkHandoffArrivals` `continue`s forever.
3. A new request for the same taskId overwrites a live record and orphans its lines.

Purpose: the phase goal is "never a fabricated animation". A figure typing in the middle of the floor, or a stale "X accepts ..." claim, is exactly that. 05-13's suite missed it because `finishWalk` teleports the sender past the real loop.

Output: `stepOffice` (the production per-frame update, exported), a walk-preserving status upsert, frozen-means-frame-only in `updateCharacter`, a single `retireHandoff` that ends a record from every exit path, seven real-loop tests plus one glyph test, and a positive accepted-line assertion in the live harness.
</objective>

- `packages/pixel-office/src/index.ts`
  - `upsertCharacterFromAgent(agentId, status, name?)`: `resolveStatusVisual(status)`. A null pose deletes the character (OFFLINE despawn). Otherwise it creates the character at `nextDeskPosition()` if it is new, then unconditionally sets `ch.state = visual.pose`, `ch.bubbleType = visual.bubble ?? null`, `ch.frozen = visual.frozen ?? false`, `ch.frameSpeedMultiplier`, and `ch.name`. A ponytail note there calls the handoff-bubble overwrite a flicker risk.
  - `startGameLoop(canvas)` passes the fork loop an `update: (dt) => { for each character updateCharacter(ch, dt); checkHandoffArrivals(); }` closure plus a `render` closure.
  - `getCharacter`, `getTileMap`, `getTaskTitle` are the accessors the FSM imports back from index.ts. The circular import is safe because it is used only inside function bodies.
- `packages/pixel-office/src/engine/characters.ts` (forked, MIT header)
  - `updateCharacter(ch, dt)`: `if (ch.frozen) { frame = 0; frameTimer = 0; return; }` sits before the switch. That early return stops WALK movement as well as animation.
  - The WALK case advances the frame every `WALK_FRAME_DURATION_SEC`. When `path` empties, it snaps to the tile centre and sets `state = IDLE`. Otherwise it moves `WALK_SPEED_PX_PER_SEC / TILE_SIZE * dt` toward `path[0]`.
  - `walkCharacterTo` calls `findPath`. `findPath` returns `[]` when start equals target, and `walkCharacterTo` then no-ops: the state is unchanged and the old path is kept.
- `packages/pixel-office/src/status/status-mapping.ts`: frozen statuses are BLOCKED, WAITING_FOR_AGENT and WAITING_FOR_CEO (all pose IDLE). CODING's pose is TYPE.
- `packages/pixel-office/src/handoff/handoff-choreography.ts`
  - `HandoffRecord { taskId, fromAgentId, toAgentId, phase, acceptedText }`. Phases: WALKING_TO_RECEIVER -> ICON_VISIBLE (set by `checkHandoffArrivals` on sender arrival: `bubbleType = "handoff-task"` plus the requested line) -> RETURNING_TO_DESK (set by the completion event: sender icon and line cleared unconditionally, sender walks home, receiver TYPE plus the accepted line) -> deleted when the sender is IDLE with an empty path.
  - `handledHandoffRequestIds` dedups by event id.
- `packages/pixel-office/src/handoff/dialogue-templates.ts`: requested is `Handing off "<title>" to <name>`, accepted is `<name> accepts "<title>"`. Neither changes in this plan.
- `Character.bubbleText?: string | null`. A freshly created character has it `undefined`, so assert a re-created character's line with `?? null` then `toBeNull()`.
- Desk slots for an IDLE-seated sequence on the default grid: slot k sits at col 1+k, row 3. Seating `agent-a, filler-1, filler-2, filler-3, agent-b, agent-c` puts a at col 1, b at col 5 (a 4-tile walk of about 1.33 s at 48 px/s) and c at col 6.
