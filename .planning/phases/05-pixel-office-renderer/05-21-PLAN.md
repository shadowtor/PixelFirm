<objective>
Close UAT gap G-05-1a (High): at native 320x176 the status glyphs are unreadable. Root cause (.planning/debug/glyph-native-scale.md): the office is always rendered at zoom 1 and nothing upscales it — `index.ts` calls `renderFrame` without its zoom argument and `App.tsx` sizes the canvas at exactly 320x176 with no scale and no `image-rendering: pixelated`.

Fix: a minimum integer display scale, implemented as ENGINE zoom (backing store 320N x 176N, `renderFrame(..., N)`), not a CSS-only upscale. Planner decision: the debug note calls CSS-only the laziest route, but engine zoom is chosen because plan 05-27 (G-05-1b) needs text drawn at device resolution to make the handoff label compact and still readable — a CSS-upscaled 320 px backing store cannot render a small crisp font. The renderer's zoom path already works end to end (the debug experiment proved zoom 3 is exactly x3).

This serves D-03 (the stuck-state glyph overlay must read at a glance) and OFFICE-03.

Purpose: every later plan in this round (layout, label, glyph anchoring) is judged at stream scale; this plan makes stream scale the only scale.
Output: `MIN_DISPLAY_SCALE` + `displayScaleFor` exported from pixel-office, zoom threaded into the render loop, App sizing/resize/pixelated styling, body margin 0, harness scale assertions, UI-SPEC spacing note.
</objective>
