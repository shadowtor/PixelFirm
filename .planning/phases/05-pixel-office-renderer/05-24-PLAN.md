<objective>
Main render slice of UAT gap G-05-1e (the user's "largest visual gap"): the office is a bare grey rectangle. Root cause (.planning/debug/office-bare-floor.md): 05-01 trimmed the fork's layout/furniture layer as a temporary tracer measure and no later plan re-added it, so `renderTileGrid` can only paint two flat colours.

This plan re-adds a small, fixed, furnished layout built on the MetroCity Interior sprites from 05-22: one data file, a layout module, a tile-sprite + z-sorted furniture render pass, and a sprite cache so the textured floor stays cheap. The seat model that consumes the layout's seats (seating, overflow, seated offset) is 05-25; furniture-blocked paths and handoff interaction tiles are 05-27; the live harness is rebased in 05-26.

Layout rationale (planner decision, verified against the sprite data): at zoom 1 a standing agent on row r has its head at y = 16r - 21 and its glyph ink at about 16r - 34 .. 16r - 23, so seat row 4 keeps every glyph fully on the floor (y >= 30 > 16) and seat row 8 keeps its glyph (about y 89..105) clear of the row-4 agents (sprite bottom 72). Putting every seat and standing spot on rows 4 and 8, with desks (or right-strip furniture) directly below them, is a property of the layout itself: the strip under each seat row's feet holds only furniture, never an agent or a glyph. 05-28 uses that strip for the handoff bubble and guards it with a test computed from this file's data, which goes red if a later layout edit intrudes on it — the bubble does not silently depend on this plan's numbers. A two-row top wall was rejected because it cannot fit two seat rows with glyph headroom.

Decisions honoured: D-03 (glyph overlay untouched), D-05 (only 05-22's audited MetroCity sprites are wired).

Output: office-layout.json, officeLayout.ts, furnished renderer with sprite cache.
</objective>
