This is a real gap in "live status updates for an open session," distinct from and outside the four defects (CR-01/CR-02/WR-01/WR-02) 05-05/05-06/05-07 close, and outside the invisible-sprite/no-bubble-render gaps 05-06/05-07 close. It is NOT one of this phase's 5 requirement IDs' scoped gaps per 05-VERIFICATION.md, and fixing it properly (a live-projection-diff broadcast, not a raw-event relay) is a meaningfully-sized architectural change, not a bug fix — out of this closure plan set's context budget (planner_authority_limits: context-cost justification). This plan's own proof design below works entirely within already-correctly-wired paths (the snapshot/fold path for status changes, the dedicated `handleHandoffEvent` path for handoffs) so it is not blocked by this gap — but the gap itself is real and should be flagged for whoever plans Phase 6 (the CEO dashboard will have the identical live-update need).
