<objective>
Close 05-VERIFICATION.md **gap 4** (review CR-02, confirmed by the verifier at two sites): in `packages/claude-adapter/src/claude-code-runtime.ts`, `record.inFlight` is one shared field on the task record while its writer is per-invocation. `attemptGracefulStop` returns `false` by *timing out* — it does not wait for the abort to drain — so the superseded invocation's `finally` later runs `record.inFlight = false` on a record its successor now owns. A third `sendMessage`/`resumeTask` then sees `false`, skips the stop branch, and starts a third concurrent `query()`, orphaning the successor's controller, watchdog and role poll where `pauseTask`/`cancelTask` cannot reach them — verbatim the defect 05-11's CR-03 fix exists to prevent. The watchdog callback's `record.status = "blocked"` has the same shape.

**Root cause, fixed once.** Every per-invocation writer of shared record state gets the same guard: an ownership token (`record.currentRun`, a fresh object per invocation) and one predicate, `isCurrent()`. The review named two sites (the `finally` and the watchdog); the same stale-write shape exists at the message loop (a superseded stream's late `result` would emit `failed` or `completed` for a task its successor is running — a fabricated status the office would render), at the role-poll tick (an orphan poll that never stops), and at the two callbacks each invocation hands to `query()` — `canUseTool` and the `Notification` hook — which both call `requestReview`, and `requestReview` sets `record.status = "waiting_for_review"` and emits it. A superseded, still-live stream firing either would overwrite the successor's status with a fabricated waiting state. Guarding only the two named sites would leave the siblings broken.

This is Phase 4 code (RUNTIME-01/02); it is in Phase 5's gap list because a stale status write reaches the office as a fabricated agent state (OFFICE-01) and because 05-11 introduced the flag.

Purpose: one live Claude Code process per task, always reachable by pause/cancel.
Output: an ownership-guarded runQuery and the multi-invocation tests the suite has never had.
