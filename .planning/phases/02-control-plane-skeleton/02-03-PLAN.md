<objective>
Build the admin credential-management surface (issue/list/revoke worker credentials, D-03) as three small Fastify routes gated by a single bootstrap-secret env var, harden all mutating control-plane endpoints with per-route rate limiting, and lock in the header-only CSRF posture (RESEARCH.md Pattern 5) by never registering a cross-origin plugin. This closes SEC-01 (credential protection scope), SEC-03 (no exec-shaped endpoint), and SEC-04 (input validation, rate limiting, CSRF) for everything this phase's surface exposes.

Purpose: Phase 6's CEO dashboard reuses these exact admin routes later (swapping the bootstrap-secret guard for a real CEO session) — building them now as a clean CRUD surface avoids rebuilding the logic from scratch.
Output: `/admin/workers` issue/list/revoke routes; rate limiting on every mutating route in the phase; a green integration test proving the credential-secrecy and rate-limit guarantees; an automated route-table audit proving no exec-shaped endpoint exists.
</objective>

  <action>
    Create apps/api/src/routes/admin-workers.ts exporting `async function registerAdminWorkersRoute(fastify)`. Define an internal `requireBootstrapSecret(request, reply): boolean` helper: read `request.headers["x-bootstrap-secret"]` (a string or undefined), compute a length-normalized `crypto.timingSafeEqual` comparison against `env.BOOTSTRAP_SECRET` (pad/compare via `Buffer.from` on both sides, checking length equality before calling `timingSafeEqual` exactly like `verifyCredential` does — RESEARCH.md Pitfall 5: a naive `===` here reintroduces the same timing side-channel `verifyCredential` was built to avoid). When the check fails, call `reply.code(401).send({ error: "unauthorized" })` and return false; the caller returns immediately when this helper returns false. Define `IssueWorkerBody = z.object({ label: z.string().min(1).max(200).optional() })` using Zod (manual `.safeParse()`, matching the repo's existing convention — no `fastify-type-provider-zod`, per RESEARCH.md Pattern 3/Don't Hand-Roll).

    Register three routes:
    - `POST /admin/workers`: `requireBootstrapSecret` first; `IssueWorkerBody.safeParse(request.body)`, 400 on failure; generate `workerId = crypto.randomUUID()`; call `issueCredential(workerId)` from `../auth/credentials`; `db.insert(workers).values({ id: workerId, secretHash, label: body.label ?? null }).returning({ id: workers.id, label: workers.label, createdAt: workers.createdAt })`; reply `201` with `{ workerId, token, label, createdAt }` — this is the only response that ever contains `token` (the raw secret half).
    - `GET /admin/workers`: `requireBootstrapSecret` first; `db.select({ id: workers.id, label: workers.label, createdAt: workers.createdAt, revokedAt: workers.revokedAt }).from(workers)` — an explicit column list that structurally excludes `secretHash`, never a `select *`; reply `200` with the array.
    - `POST /admin/workers/:id/revoke`: `requireBootstrapSecret` first; `db.update(workers).set({ revokedAt: new Date() }).where(eq(workers.id, request.params.id)).returning({ id: workers.id, revokedAt: workers.revokedAt })`; if the returned array is empty, reply `404` with `{ error: "not found" }`; otherwise reply `200` with the single updated row.

    Edit apps/api/src/server.ts: add `fastify.register(registerAdminWorkersRoute)` alongside the existing route registrations.
  </action>
  <acceptance_criteria>
    - All three routes return 401 when `X-Bootstrap-Secret` is missing or wrong, before any body/param validation runs.
    - POST /admin/workers with the correct secret and a valid body returns 201 with `workerId`, `token` (shaped `workerId.secret`), `label`, `createdAt`.
    - GET /admin/workers's response items never contain a `secretHash` or `token` key.
    - POST /admin/workers/:id/revoke sets `revokedAt` for a known id and returns 404 for an unknown one.
  </acceptance_criteria>
